# Runtime language

| Term | Meaning |
| --- | --- |
| Runtime service | Claims an owner epoch, recovers durable work and maintains readiness |
| Owner epoch | Opaque authority binding for the runtime lease and admitted episodes |
| Recovery report | Episode attempts and evidence calls repaired with ownership claim |
| Pipeline | Owner-scoped orchestration of stream, admission, episodes, policy and actions |
| Batch report | Durable stages counted during one source advancement |
| Worker runtime | Executor and evidence connection resources owned by the process |
| Source | Normalized trace, simulator trace or live UDS ingress adapter |
| Approval presentation | Tenant-scoped immutable evidence and decision-bound signing bytes |
| Maintenance | Watch expiry and durable approved-command delivery without new input |
| Governed route | Watch, closed device or fallback effect path retaining final authorization |

Retire numbered phase names from new code. Preserve established identities and
wire/data names; names describe responsibilities rather than extraction rounds.
