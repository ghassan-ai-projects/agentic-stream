# A-003 · `internal/episodes/executor.go`

LOC: 851 · Audit date: 2026-09-11 · Verdict: FINDINGS

## Bar (close only when every line is true)
- The terminal persistence transaction (decision, intents, attempt transition, episode conclusion) runs on the cancellation-proof `persistCtx`, not the caller's cancellable `ctx`.
- An epoch-kill quarantine (`lifecycle_status='abandoned'`) is durably committed, never rolled back by the error return that follows it; no `ExecContext` error on a quarantine write is swallowed.
- `budget.wall_time` from `RequestJSON` is parsed and validated in exactly one place shared by the deadline gate and the worker executor.
- Every exported symbol has at least one caller (`Executor.Name()` verified repo-wide).
- `ctx` vs `persistCtx` usage is uniform across the three post-execute persistence paths; no `json.Marshal`/`Unmarshal` error is discarded with `_`.
- Dispatch ordering (`ORDER BY accepted_at`) is a correct chronological total order for the timestamp format actually written.

## Findings
- **HIGH F1. Success-path persistence uses the cancellable parent ctx, defeating `WithoutCancel` and silently losing produced decisions** — `internal/episodes/executor.go:350-504`. `persistCtx` is built at line 350 precisely to survive cancellation (`context.WithoutCancel(ctx)` + 5s), but the `withTx(persistCtx, ...)` closure at 368 closes over `RunOnce`'s `ctx` parameter and uses it for every statement (375, 377, 423, 426, 445, 449, 453, 462, 465, 488, 492, 496). Proven empirically: cancel `ctx` while the executor succeeds → `RunOnce` returns `tx: allocate decision ordinal: context canceled`, the produced decision/intents roll back, and the attempt+episode are left `running` with a non-terminal attempt. The next `RunOnce` then fails `StartAttempt` ("already has active attempt") on the oldest row, and `internal/runtime/pipeline.go:387-390` aborts the whole batch — the tenant dispatch loop is dead until a restart recovers the attempt. Fix: make `withTx` pass its ctx into the closure (or capture `persistCtx` explicitly) and use it for all statements in this transaction.
- **HIGH F2. Epoch-kill gates roll back their own quarantine, poisoning the dispatch queue** — `internal/episodes/executor.go:264-273, 374-383`. Both gates execute `UPDATE episodes SET lifecycle_status='abandoned'` and then `return fmt.Errorf(...)`, which rolls the quarantine back inside the same tx — contradicting the comments ("The episode is quarantined") and the committed-quarantine pattern the stale paths at 203-258 deliberately use (`return nil`). The dispatch-time variant is reachable via the TOCTOU between `AssertAdmission` (pipeline.go:461-463, outside the admission tx) and `Kill`'s supersede UPDATE (epoch_control.go:43-46): an episode admitted under a just-killed epoch escapes the supersede, then fails the gate at 264 — the UPDATE rolls back, the episode stays `admitted` as the always-oldest row (142-143), and every `RunOnce` returns an error, aborting every pipeline batch until an operator intervenes. The accompanying `_, _ = tx.ExecContext(...)` at 218, 248 also swallows quarantine write errors (P1). Fix: commit the quarantine and return nil (as the stale path does), check the `ExecContext` error, and return the refusal reason in the terminal record rather than as a tx-rollback error.
- **MED F3. `budget.wall_time` parsed four times with divergent failure semantics** — `internal/episodes/executor.go:689-703`; also `internal/episodes/worker_executor.go:326-346, 533-539` and `internal/episodes/assembler.go:322-331`. `deadlineExceeded` silently treats a missing or unparseable `wall_time` as "no deadline", while `boundedExecutionContext` hard-fails on the same input, and `episodeRequest` parses it a second time within the same `Execute` call. The freshness gate (364-366) and the worker's context deadline can therefore drift apart on the identical durable field. Fix: parse/validate the budget once at bind time into typed `Request` fields and have both consumers read that.
- **LOW F4. `Executor.Name()` is dead interface surface** — `internal/episodes/executor.go:29-34`. Repo-wide grep finds zero callers; the ledger's `executor_name` comes from the spec via the assembler (`assembler.go:338`), never from `Name()`. All three implementations (`WorkerExecutor`, `FakeExecutor`, `internal/executor/native`) implement it for nothing. Remove the method or actually record it.
- **LOW F5. Inconsistent ctx usage and discarded marshal errors** — `internal/episodes/executor.go:358, 215, 246, 266, 376, 409-418`. `failAttemptWithRejection` at 358 gets `ctx` while its sibling failure paths (343, 348, 365) get the cancellation-proof `persistCtx`; `terminal, _ := json.Marshal(...)` and `validationJSON, _ = ...` discard errors. All current values are marshal-infallible, but the bar is "none swallowed". Fix: propagate and wrap.
- **LOW F6. `ORDER BY accepted_at` is not a correct chronological order for RFC3339Nano** — `internal/episodes/executor.go:142-143`. `Format(time.RFC3339Nano)` trims trailing zeros, so a whole-second stamp (`…T10:00:00Z`) sorts lexicographically after `…T10:00:00.5Z` while being chronologically earlier; dispatch order and the "always the oldest row" quarantine reasoning can invert across writers of mixed precision (test seeds already use whole-second stamps). Fix: order by `(accepted_at, episode_id)` on a fixed-precision format or a monotonic numeric column.

## Checked, not an issue
- P1: errors from SQL, validation, digest, and cost paths are wrapped with `%w` and propagate; no data races found (goroutine shares only `episodeID`; `req` is goroutine-local).
- P2: episodes bind one validated snapshot version; decisions are validated (digest, identity binding, catalog) before any intent row is written; shadow dispatch never writes intents/commands (`recordShadow` fails closed without a store); supersession watch and deadline gate honor cancellation.
- P7: fencing via monotonic `fence` per episode, bounded retries (`maxEpisodeAttempts`), durable `stale_rebind_count` budget, idempotent `RecordRejection` by content hash.
- P5: slog used, canonical JSON (RFC 8785) for all digests, intent catalog verified independently of the worker (B10).
- P6: runner/rebind/p8/shadow/cancellation tests cover dispatch, staleness, kill, shadow, and retry-limit behavior.
