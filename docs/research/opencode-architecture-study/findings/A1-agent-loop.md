# A1 — Agent Loop & Session Core: Deep Architectural Analysis

Repo: `anomalyco/opencode` dev @ a19b52e85bf2 (2026-07-20). All paths relative to repo root. Verified read-only against source.

## 0. Architecture map: three coexisting layers

The session core is mid-migration. Three layers coexist and are all wired into the server layer graph (`packages/opencode/src/server/routes/instance/httpapi/server.ts:301`):

1. **V1 production loop — `packages/opencode/src/session/`**. `SessionPrompt` (prompt.ts), `SessionProcessor` (processor.ts), `LLM` (llm.ts), `Session` (session.ts). This is the live agent loop serving the HTTP endpoints (`server/routes/instance/httpapi/groups/session.ts` imports SessionPrompt). Written as Effect-TS services composed with `LayerNode` (dependency-injected `Context.Service`s, e.g. `session.ts:476` `@opencode/Session`).
2. **V2 durable foundation — `packages/core/src/`**. Event-sourced infrastructure that V1 already uses: `event.ts` (durable event log + PubSub), `session/projector.ts` (event→relational projections), `session/sql.ts` (tables), `agent.ts`, `background-job.ts`. It also contains the **next-gen runner** `core/src/session/runner/llm.ts` — a from-scratch durable agent loop whose own docstring (lines 43–90) is a checklist marking it work-in-progress ("Keep this as orchestration over smaller collaborators rather than rebuilding the legacy `SessionPrompt` monolith"). It is constructed (`SessionExecution.node`, `SessionExecutionLocal.node`) but V1 remains the production prompt path.
3. **Canonical LLM library — `packages/llm/`**. Provider protocol implementations (anthropic-messages, openai-responses, bedrock-converse, gemini…), model routing (`route/`), canonical `LLMEvent`/`LLMRequest` schema, `tool-runtime.ts`, `cache-policy.ts`. V1 reaches it only through the opt-in "native runtime" seam (see §2); the V2 runner uses it directly via `LLMClient`.

`packages/opencode/src/session/llm/AGENTS.md` documents the seam explicitly: default runtime = AI SDK `streamText`; `native-runtime.ts` is the opt-in adapter over `@opencode-ai/llm`; both converge on the same `LLMEvent` stream so the processor is runtime-agnostic.

## 1. Session lifecycle

### 1.1 Creation & shape
`Session.Service` (`packages/opencode/src/session/session.ts:476`) is the session aggregate. `create` → `createNext` (`session.ts:501–540`) builds an `Info` (`session.ts:224–244`): `id` (descending ULID, `SessionID.descending`), `slug`, `projectID`, optional `parentID` (subagent sessions), `title` (`"New session - <ISO>"` / `"Child session - <ISO>"`, `session.ts:48–55`), `agent`, `model {id, providerID, variant}`, `summary {additions,deletions,files,diffs}`, `cost`, `tokens {input,output,reasoning,cache{read,write}}`, `share {url}`, `revert {messageID,partID,snapshot,diff}`, `permission` ruleset, `time {created,updated,compacting,archived}`. Every mutation publishes a durable event (`session.ts:537` publishes `SessionV1.Event.Created`; `patch` at `session.ts:736–749` publishes `Updated`).

### 1.2 Message model
Defined in `packages/schema/src/v1/session.ts`, re-exported as `SessionV1` via `packages/core/src/v1/session.ts`.

- **User** (`v1/session.ts:332–354`): `role:"user"`, `agent`, `model{providerID,modelID,variant}`, optional `format` (text | json_schema), `tools` overrides, `system` prompt override, `summary.diffs`.
- **Assistant** (`v1/session.ts:453–485`): `parentID` (the user message it answers), `modelID/providerID`, `mode`/`agent`, `cost`, `tokens`, `finish` reason, `error` (discriminated union: AuthError, AbortedError, APIError, ContextOverflowError, ContentFilterError, StructuredOutputError, OutputLengthError, Unknown — `:385–394`), `summary:true` for compaction summaries, `structured` output, `path{cwd,root}`.
- **Parts** (`v1/session.ts:357–370`) — 12 variants: `text`, `reasoning`, `tool`, `file`, `step-start`, `step-finish`, `snapshot`, `patch`, `agent`, `subtask`, `retry`, `compaction`.
- **Tool part** is itself a state machine (`v1/session.ts:259–313`): `pending{input,raw}` → `running{input,title?,metadata?,time.start}` → `completed{output,title,metadata,time{start,end,compacted?},attachments?}` | `error{error,metadata?,time}`. `time.compacted` marks pruned outputs (see §3).

### 1.3 Persistence: event sourcing with relational projections
Writes are **event-sourced**. All state changes go through `events.publish` of **durable** events — declared `durable: { aggregate: "sessionID", version: 1 }` (`v1/session.ts:502–507`; events: `session.created/updated/deleted`, `message.updated/removed`, `message.part.updated/removed`). `message.part.delta` (`v1/session.ts:632–641`) is deliberately **not durable** — transient streaming only.

`EventV2.commitDurableEvent` (`packages/core/src/event.ts:205–366`) is the commit path: inside a single SQLite `immediate` transaction it (a) reads/increments the per-aggregate sequence in `EventSequenceTable`, (b) runs registered **projectors** in the same transaction, (c) upserts the sequence row, (d) appends to `EventTable` with `versionedType(type, version)`. Replay is guarded by optimistic concurrency: seq mismatch or payload divergence → `InvalidDurableEventError` die (`event.ts:284–302`); owner-claim via `owner_id`.

Projections live in `packages/core/src/session/projector.ts`: `PartUpdated` upserts `PartTable` and re-applies usage rollups onto `SessionTable` with signed add/subtract (`applyUsage`, `projector.ts:90–110`, `312–330`); `MessageUpdated` upserts `MessageTable` (`:262–275`); revert events delete projected rows past the boundary (`:415–453`). Reads hit the projections, not the log: `MessageV2.page` (`packages/opencode/src/session/message-v2.ts:425–467`) paginates `MessageTable` newest-first with a base64url `(time,id)` cursor, `hydrate` joins parts (`:98–123`). The legacy V1 session service is thus a thin event-publishing façade over the V2 event store.

### 1.4 Fork / revert / share
- **Fork** (`session.ts:693–734`): new session (`"<title> (fork #N)"`, `:161–169`), copies messages up to an optional `messageID`, re-issues ascending `MessageID`/`PartID`s, remaps assistant `parentID` and compaction `tail_start_id` through an id map.
- **Revert** (`packages/opencode/src/session/revert.ts`): two-phase. `revert` (`:38–88`) asserts not-busy, walks messages to the target, captures a git **snapshot** (`Snapshot.track`), undoes file changes by reverting `patch` parts (`snap.revert(patches)`), stores `session.revert{messageID,partID,snapshot,diff}` plus a diff summary. Messages are only deleted lazily by `cleanup` (`:100–134`) at the start of the next prompt (`prompt.ts:1056`) — so revert is undoable (`unrevert` restores the snapshot, `:90–98`).
- **Share**: `setShare` stores a `share_url` on the session row (`session.ts:812–814`); row also tracks `summary`, `cost`, token rollups.
- **Delete**: recursive over children, cancels matching background jobs (`session.ts:608–629`, `940–955`).

## 2. The step loop

### 2.1 Entry and single-runner guarantee
`SessionPrompt.prompt` (`prompt.ts:1052–1071`): `revert.cleanup` → `createUserMessage` (`:635+`; resolves `@file`/`@agent` mentions, MCP resources, data/file URLs into parts) → `sessions.touch` → optional permission override from `input.tools` → `loop({sessionID})` unless `noReply`.

`loop` (`:1343–1347`) = `state.ensureRunning(sessionID, onInterrupt, runLoop)`. `SessionRunState` (`run-state.ts:35–69`) keeps one `Runner` per session; `Runner.make` (`packages/opencode/src/effect/runner.ts:39–215`) is a **state machine** `Idle | Running | Shell | ShellThenRun` (`runner.ts:33–37`): `ensureRunning` joins the in-flight run's `Deferred` if already running (prompt coalescing), otherwise forks the work fiber in the instance scope; `cancel` interrupts the fiber and completes waiters with `Cancelled`; a shell command (`!`-prefix) can occupy the session first, queueing the pending run (`ShellThenRun`). `onIdle` flips `SessionStatus` to idle and deregisters (`run-state.ts:60–65`).

### 2.2 The loop construct — hand-rolled, not AI SDK maxSteps
`runLoop` (`prompt.ts:1081–1341`) is an explicit **`while (true)`** (`:1088`) inside an Effect generator. The AI SDK is used strictly per-turn (`streamText` with `maxRetries: input.retries ?? 0`, `llm.ts:323`); the SDK's `maxSteps`/`stopWhen` are **not** used — step accounting, continuation, compaction and step limits are owned here. Per iteration:

1. `status.set(busy)`; reload history via `MessageV2.filterCompactedEffect` (`:1092`).
2. Derive bindings with `MessageV2.latest` (`message-v2.ts:585–601`) — max-id `user`/`assistant`/`finished`, plus unprocessed `tasks` (compaction/subtask parts on user messages newer than the last finished assistant).
3. **Exit test** (`:1111–1130`): break when the last assistant has a `finish` ≠ `tool-calls`, no unfinished tool parts remain (ignoring orphan interrupted tools, `isOrphanedInterruptedTool` `:96–100`), and `lastUser.id < lastAssistant.id`. The comment at `:1103–1109` documents why: some providers return `stop` even with pending tool calls.
4. `step++`; on step 1 fork title generation (`:1133–1139`, small-model `llm.stream` with `retries: 2`, `:225–242`).
5. Dispatch queued tasks: `subtask` → `handleSubtask` then `continue`; `compaction` → `compaction.process`, break on `"stop"` (`:1144–1159`). **Overflow pre-check**: if last finished assistant tokens overflow the model, `compaction.create({auto:true})` and continue (`:1161–1168`).
6. Resolve agent (`:1170–1177`), `maxSteps = agent.steps ?? Infinity` (`:1178`); on the last allowed step a synthetic assistant message `MAX_STEPS_PROMPT` ("Tools are disabled… respond with text only", `core/src/session/runner/max-steps.ts:1–16`) is appended (`:1281`).
7. `SessionReminders.apply` injects synthetic plan-mode/build-switch text parts (`reminders.ts:15–90`).
8. Create+publish the assistant message (`:1186–1201`), then `processor.create` (`:1213–1219`) guarded by `Effect.onInterrupt(finalizeInterruptedAssistant)` stamping `AbortedError` + `time.completed` (`:1203–1211`).
9. `SessionTools.resolve` builds the AI SDK tool set (`:1226–1241`); json_schema sessions get a forced `StructuredOutput` tool with `toolChoice:"required"` (`:1243–1250`, `:1285`).
10. Assemble system context and convert history (`:1257–1269`, §4), then `handle.process({...})` (`:1272–1286`).
11. Outcome mapping (`:1288–1329`): structured output → break; `content-filter` finish → synthesize `ContentFilterError` + `session.error`, break; `"stop"` → break; `"compact"` → `compaction.create({auto:true, overflow:!finish})`, continue. `Effect.ensuring(instruction.clear(...))` resets per-message instruction claims (`:1331`).

After the loop, `compaction.prune` is forked and the last assistant message returned (`:1338–1339`).

### 2.3 One step: processor and the tool-call protocol
`SessionProcessor.process` (`processor.ts:627–683`) runs exactly one provider turn:

```ts
const stream = llm.stream(streamInput)
yield* stream.pipe(
  Stream.tap((event) => handleEvent(event)),
  Stream.takeUntil(() => ctx.needsCompaction),
  Stream.runDrain,
)
```
(`processor.ts:640–646`). It is wrapped in `Effect.retry(SessionRetry.policy(...))` (`:660–674`), `Effect.catch(halt)` (`:675`), `Effect.ensuring(cleanup)` (`:676`); on interrupt it marks `aborted` and halts with an `AbortError` (`:648–655`). Result: `"compact" | "stop" | "continue"` (`:679–681`).

`handleEvent` (`:278–537`) folds the `LLMEvent` stream into parts: `reasoning-start/delta/end` maintain a reasoning map with **delta-only** publishes (`updatePartDelta`); `tool-input-start/delta/end` → `ensureToolCall` (pending part + a `Deferred` per call); `tool-call` → running part, then the **doom-loop guard** (`:356–380`): if the last `DOOM_LOOP_THRESHOLD = 3` tool parts are the same tool with identical input, `permission.ask({permission:"doom_loop"})`; `tool-result` → `completeToolCall` (image attachments normalized/resized, `:390–412`); `tool-error` → `failToolCall` — a permission/question rejection sets `ctx.blocked` so the loop stops (`:200–202`, `config.experimental.continue_loop_on_deny` overrides, `:633`); `step-start/step-finish` → git snapshot (`Snapshot.track`), usage accounting (`Session.getUsage`), a `patch` part diffed from the snapshot (`:457–470`), a forked summary update, and the overflow check that sets `needsCompaction` (`:477–482`); `provider-error` throws. `cleanup` (`:539–597`) finalizes open text/reasoning parts, awaits tool `Deferred`s (250 ms), and fails unsettled calls with `"Tool execution aborted"` + `metadata.interrupted:true` — the marker the loop's orphan check reads.

Tool **execution** is delegated to the AI SDK inside `streamText`: `SessionTools.resolve` (`tools.ts:92–134`) wraps each registered tool with plugin hooks (`tool.execute.before/after`) and a `Tool.Context` (`tools.ts:59–90`) exposing `metadata` (streams progress into the tool part via `processor.updateToolCall`) and `ask` (`permission.ask` merged agent+session rulesets). A GitLab workflow variant even bridges server-side tool calls over WebSocket into the same executor (`llm.ts:115–206`).

### 2.4 LLM streaming and runtime selection
`LLM.stream` (`llm.ts:357–381`) scopes an `AbortController` (`Effect.acquireRelease`, abort on scope close) and calls `run` (`:85–355`): resolve language model/config/provider/auth, then `LLMRequestPrep.prepare` (`llm/request.ts:56–206`) — system assembly, provider-options merge (`base→model→agent→variant`), temperature/topP/topK/maxOutputTokens via plugin hook `chat.params`, session-sticky headers, tool filtering by permission + user overrides (`resolveTools`, `:208–214`), OpenAI-Responses `strict:false` normalization, Copilot `_noop` workaround. Runtime gate (`llm.ts:226–269`): if `flags.experimentalNativeLlm` and the provider is supported (openai/anthropic/opencode only, `native-runtime.ts:50–72`), use the native `@opencode-ai/llm` path; otherwise log the fallback reason and use `streamText` with `experimental_repairToolCall` (`:296–312`: case-mismatched names lowercased, unrepairable calls routed to an `invalid` tool), `wrapLanguageModel` middleware applying `ProviderTransform.message` (incl. caching), and OTel telemetry. AI SDK `fullStream` parts are adapted to canonical `LLMEvent`s by `LLMAISDK.toLLMEvents` (`llm/ai-sdk.ts:76+`), so the processor consumes one event algebra regardless of runtime (`packages/llm/src/schema/events.ts`: `step-start`, `text-*`, `reasoning-*`, `tool-*`, `finish`, `provider-error`).

### 2.5 Aborts, interrupts, retries, errors
- **Cancel**: `SessionPrompt.cancel` → `SessionRunState.cancel` (`run-state.ts:77–86`) cascades background-job cancellation (`:111–143`, iterative descendant set) then `Runner.cancel` → fiber interrupt. The scope release aborts the HTTP request (`llm.ts:361–364`).
- **Retry policy** (`retry.ts`): `policy` (`:176–199`) is an Effect `Schedule.fromStepWithMetadata` that retries **unbounded** while `retryable()` returns a reason. `delay` (`:35–66`): honor `retry-after-ms`/`retry-after` headers (capped at 2³¹−1 ms), else exponential `2000·2^(attempt−1)` capped at 30 s when no headers (`RETRY_INITIAL_DELAY/BACKOFF_FACTOR/MAX_DELAY_NO_HEADERS`, `:26–29`). Retryable (`:68–152`): `ContextOverflowError` never; `APIError` when `isRetryable` or status ≥ 500 ("5xx … always be retried"); special-cased provider bodies — `FreeUsageLimitError` → Go upsell action, `GoUsageLimitError` → account rate-limit action with humanized reset time; plain-text/JSON rate-limit patterns. Each attempt publishes `SessionStatus {type:"retry", attempt, message, action, next}` (`processor.ts:664–672`). Separately, the packages/llm transport has its own bounded retry: `RequestExecutor.retryStatusFailures` (`packages/llm/src/route/executor.ts:353–364`) — `MAX_RETRIES=2`, statuses 429/503/504/529, `retryAfterMs` honored, jittered backoff 500·2^a ±20% capped 10 s, with aggressive credential redaction (`:48–75`).
- **Error normalization**: `MessageV2.fromError` (`message-v2.ts:603–731`) maps DOMException AbortError→`AbortedError`, `LoadAPIKeyError`→`AuthError`, ECONNRESET/Zlib decompression/header-timeout/stream errors→retryable `APIError`, `APICallError`→parsed (`context_overflow`→`ContextOverflowError`), else `Unknown`. `halt` (`processor.ts:599–625`): context overflow → `needsCompaction` (auto-compact) unless `compaction.auto===false` (then terminal error + idle); other errors → message error + `session.error` event + idle.

## 3. Context-window management

- **Budget** (`overflow.ts`): `usable()` = `limit.input − reserved` (reserved = `config.compaction.reserved` or `min(COMPACTION_BUFFER=20_000, maxOutputTokens)`), else `context − maxOutputTokens`. `isOverflow` when `tokens.total` (or the summed parts) ≥ usable; disabled when `compaction.auto===false` or context limit 0.
- **Triggers**: (a) post-turn check in the loop (`prompt.ts:1161–1168`); (b) `step-finish` check in the processor (`processor.ts:477–482`) → stream truncated via `Stream.takeUntil(needsCompaction)` → `"compact"`; (c) provider-rejected overflow (`ContextOverflowError` in `halt`).
- **Compaction protocol** (`compaction.ts`): `create` appends a user message carrying a `compaction` part (`:513–536`); the loop picks it up as a task. `process` (`:289–511`): in overflow mode, find the previous real user message as a **replay** and drop everything after it (`:310–326`); hide earlier (compaction-user, summary-assistant) pairs (`:333–336`); `select` (`:188–239`) chooses the tail to preserve — last `compaction.tail_turns` (default 2) user turns fitting `preserve_recent_tokens` (default `clamp(usable·0.25, 2_000, 8_000)`), with `splitTurn` for a partial turn. The summarizer is the hidden `compaction` agent (`agent/agent.ts:219–233`, all-deny permissions), prompted with `buildPrompt` (`packages/core/src/session/compaction.ts:161–168`) — "anchored summary" that updates the `<previous-summary>` — and a fixed Markdown template (Objective / Important Details / Work State{Completed,Active,Blocked} / Next Move / Relevant Files, `:16–46`). Media is stripped and tool outputs truncated to 2 000 chars (`compaction.ts:351–354`). On success: update `tail_start_id`, then either re-inject the replayed user message (media→text placeholders, `:422–449`) or a synthetic "Continue if you have next steps…" user message (`:473–502`, gated by plugin `experimental.compaction.autocontinue`), and publish `SessionCompactionEvent.Compacted`. If even compaction overflows, terminal `ContextOverflowError` (`:404–413`).
- **Replay view**: `MessageV2.filterCompacted` (`message-v2.ts:521–572`) rebuilds model-visible history as `[compaction-user, summary, …tail from tail_start_id, …later messages]`.
- **Prune** (`compaction.ts:243–287`): when `config.compaction.prune`, walk newest→oldest past the last 2 user turns; keep the newest `PRUNE_PROTECT=40_000` tokens of tool output; mark older completed tool parts `time.compacted` (rendered as `"[Old tool result content cleared]"`, `message-v2.ts:293–294`) once `pruned > PRUNE_MINIMUM=20_000`; `skill` tool protected; stops at summary boundaries. Forked after each run (`prompt.ts:1338`).
- **Token counting**: authoritative = provider usage on `step-finish`, normalized by `Session.getUsage` (`session.ts:338–407`) — AI SDK v6 reports inclusive input, so cache read/write are subtracted for costing; reasoning billed at output rate; context-tiered pricing supported. Estimation = `chars/4` (`packages/core/src/util/token.ts`).

## 4. System prompt construction & caching

Final assembly happens per step (`prompt.ts:1257–1269`): `[...sys.environment(model), ...instruction.system(), ...(mcp), ...(skills)]`, then `LLMRequestPrep.prepare` prepends the **base prompt** (`llm/request.ts:56–78`): `agent.prompt` if set, else `SystemPrompt.provider(model)` (`system.ts:27–42`) selecting a family file from `session/prompt/*.txt` by model id (claude→anthropic.txt, gpt→gpt.txt/codex.txt, gemini, kimi, trinity, muse-spark→meta.txt, gpt-4/o1/o3→beast.txt, else default.txt — an opencode CLI persona with tone/verbosity rules). User-supplied `user.system` is appended; the plugin hook `experimental.chat.system.transform` may rewrite; result is `[header, rest…]` joined, then emitted as system role messages (except OpenAI-oauth, where it goes into `options.instructions`, `request.ts:99–112`).

- **Environment** (`system.ts:60–96`): model identity line + `<env>` block (working dir, workspace root, is-git-repo, platform, date) + `<available_references>` from project references.
- **AGENTS.md instructions** (`instruction.ts`): global `~/.config/opencode/AGENTS.md` or `~/.claude/CLAUDE.md` (first hit, `:60–63`, gated by `disableClaudeCodePrompt`), first project-level match walking up from cwd→worktree (`AGENTS.md`/`CLAUDE.md`/deprecated `CONTEXT.md`, `:122–133`), `config.instructions` globs and remote `http(s)` URLs fetched with 5 s timeout (`:95–103`, `:155–169`); each emitted as `Instructions from: <path>\n<content>`. Separately, `instruction.resolve` (`:179–221`) attaches nearby instruction files around files the `read` tool touches — once per assistant message via a `claims` map, reset per step (`prompt.ts:1331`).
- **Skills / MCP** (`system.ts:98–128`): verbose skill catalog (permission-gated) and `<mcp_instructions>` filtered by tool permissions.
- **Caching**: legacy path — `ProviderTransform.message` (invoked from the `wrapLanguageModel` middleware, `llm.ts:325–343`) calls `applyCaching` (`provider/transform.ts:335–379`): marks the **first 2 system + last 2 non-system messages** with ephemeral cache breakpoints (`anthropic.cacheControl`, `bedrock.cachePoint`, `openrouter`, `openaiCompatible`, `copilot`, `alibaba` variants); OpenAI-family gets `promptCacheKey = sessionID` (`transform.ts:1134–1266`) and every request carries `x-session-affinity` headers (`request.ts:187–201`) — session-sticky prefix reuse. Canonical path — `packages/llm/src/cache-policy.ts`: default `"auto"` places breakpoints at the **last tool definition + last system part + latest user message** (`:18–22`), only for protocols honoring inline hints (`anthropic-messages`, `bedrock-converse`, `:42`), preserving manual `CacheHint`s; the header comment (`:5–11`) documents the tool-loop rationale.

## 5. Multi-agent mechanics

- **Definitions** (`agent/agent.ts:35–56`): `mode: "primary" | "subagent" | "all"`, permission ruleset, optional model/variant/prompt/temperature/topP/`steps`/options, `hidden`, `native`. Built-ins (`:140–265`): `build`, `plan` (primary; plan denies edit tools except plan files), `general`, `explore` (subagents; explore is read/search-only), and hidden primary agents `compaction`, `title`, `summary`. Config merges/overrides; `generate` synthesizes new agents via `generateObject` (`:368–436`). A V2 registry mirrors this in `packages/core/src/agent.ts` (state-map with selectable-default logic).
- **Spawning** — the `task` tool (`tool/task.ts`): depth check (`subagent_depth` default 1, `:104–117`), `permission.ask("task")` unless bypassed, child session created with `parentID` and derived permissions (`deriveSubagentSessionPermission` + auto-deny `todowrite`/`task` unless the agent declares them, `:139–172`), then the same `SessionPrompt.prompt` loop runs the child **in-process** (`runTask`, `:200–214`). Foreground = `Effect.raceFirst(background.wait, waitForPromotion)` with abort→cancel wiring (`:317–347`); background mode (`background=true`, flag `experimentalBackgroundSubagents`) runs as a `BackgroundJob` and injects the result back into the parent as a synthetic `<task …>` user message (`:216–254`). User-queued `subtask` parts are executed inline by `handleSubtask` (`prompt.ts:255–449`) as a `task` tool part on a fresh assistant message.
- **Run-state machine**: per-session `Runner` FSM (§2.1) plus the V2 `SessionRunCoordinator` (`packages/core/src/session/run-coordinator.ts:24–104`): per-key serialized `drain` with `pendingWake` coalescing and fiber interruption; `SessionExecutionLocal` (`core/src/session/execution/local.ts`) routes drains to the location-bound runner. `BackgroundJob` (`core/src/background-job.ts`) is an explicitly **non-durable** process-local job registry (docstring `:113–119`) with start/extend/wait/promote/cancel.

## 6. Streaming

Stream algebra: AI SDK `fullStream` (or native runtime) → canonical `LLMEvent`s (`llm/ai-sdk.ts`) → Effect `Stream` tapped by the processor. **Part-level persistence streaming**: full part states publish durable `message.part.updated` events (`session.ts:637–645`); high-frequency text/reasoning deltas publish non-durable `message.part.delta` (`session.ts:879–887`, `MessageV2.Event.PartDelta`). Fan-out: `EventV2.notify` (`core/src/event.ts:406–417`) feeds listeners + typed/global `PubSub`s; `EventV2Bridge` (`event-v2-bridge.ts:35–61`) re-emits every event on the legacy `GlobalBus` (Node `EventEmitter`, `bus/global.ts`) as `{directory, project, workspace, payload}`, plus a second `"sync"` envelope for durable events (aggregate seq included). Clients subscribe over **SSE**: `GET /event` → `text/event-stream` (`server/routes/instance/httpapi/groups/event.ts:16`). Session status transitions (`idle`/`busy`/`retry`) are themselves events (`status.ts:39–48`).

## 7. Design patterns observed

| Pattern | Where |
|---|---|
| **ReAct loop** (reason→act→observe, finish-driven exit) | hand-rolled `while(true)` `runLoop`, `prompt.ts:1088`; exit on `finish`/`tool-calls`, `:1111–1130` |
| **Event sourcing + CQRS** | durable events, per-aggregate seq, `EventTable`/`EventSequenceTable`, replay guards (`core/src/event.ts:205–366`); projections in `session/projector.ts`; reads from `MessageTable`/`PartTable` |
| **State machine** | `Runner` Idle/Running/Shell/ShellThenRun (`effect/runner.ts:33–37`); `ToolState` pending/running/completed/error (`v1/session.ts:259–313`); `SessionStatus` idle/busy/retry |
| **Retry with exponential backoff** | `SessionRetry.policy` Schedule w/ Retry-After honoring (`retry.ts:26–66,176–199`); transport-level bounded jitter retry (`route/executor.ts:345–364`) |

## 8. Where new supersedes old

- `packages/opencode/src/session/*` = **the** loop today (V1); `packages/core/src/session/runner/llm.ts` (V2 durable runner, `while (needsContinuation)` turns at `:393–405`, tool settlement via FiberSet at `:250–271`) is built and noded but its own checklist marks parity gaps (durable status, plugins, retry bounds unchecked) — it supersedes only once finished.
- Persistence is already V2: V1 `Session`/`MessageV2` are façades publishing `SessionV1` durable events into the `core` event store + projectors; `message.part.delta` stays transient by design.
- LLM calls: production default still AI SDK `streamText` (V1); `packages/llm` (protocols, route/executor, cache-policy, tool-runtime) is the canonical future, reachable today via `experimentalNativeLlm` and used directly by the V2 runner and `core` compaction.
- `core/src/session/compaction.ts` (V2, event-published `Compaction.Started/Ended`, serialized transcript selection) coexists with V1 `session/compaction.ts`; V1's `buildPrompt` is already imported from core (`compaction.ts:23`).
