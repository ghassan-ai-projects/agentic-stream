**Scope:** English docs in `packages/web/src/content/docs/*.mdx` (no `en/` folder; the top-level `.mdx` files are the English originals), repo root files (`README.md`, `AGENTS.md`, `CONTEXT.md`, `CONTRIBUTING.md`), plus opencode.ai (landing, changelog, v2 beta docs). ## 1. Documented architecture story & philosophy

### 1.1 What OpenCode says it is
- Landing page: "The open source AI coding agent… Free models included or connect any model from any provider, including Claude, GPT, Gemini and more." Feature bullets: **LSP enabled** ("Automatically loads the right LSPs for the LLM"), **Multi-session** ("Start multiple agents in parallel on the same project"), **Share links**, **Any model** ("75+ LLM providers through Models.dev, including local models"), **Any editor** ("terminal interface, desktop app, and IDE extension"). (https://opencode.ai/)
- "Built for privacy first — OpenCode does not store any of your code or context data, so that it can operate in privacy sensitive environments." (landing; repeated in `enterprise.mdx`). Scale claims: 160k+ GitHub stars, 900 contributors, 13k commits, 7.5M monthly developers.
- Docs intro (`index.mdx`): "OpenCode is an open source AI coding agent. It's available as a terminal-based interface, desktop app, or IDE extension."

### 1.2 Positioning vs Claude Code (historic FAQ, documented 2025)
The current README no longer carries the FAQ, but the project's canonical positioning survives in the 2025 README (mirrored fork, 2025-07-01): *"It's very similar to Claude Code in terms of capability. Here are the key differences:* ***100% open source**;* ***Not coupled to any provider**… 'As models evolve the gaps between them will close and pricing will drop so being provider agnostic is important';* ***A focus on TUI** — 'opencode is built by neovim users and the creators of terminal.shop; we are going to push the limits of what's possible in the terminal';* ***A client/server architecture** — 'the TUI frontend is just one of the possible clients'."* (github.com/Decentralised-AI/opencode2025 README). Every current doc is consistent with these four pillars.

### 1.3 Client/server is the core architectural claim
`server.mdx`: "When you run `opencode` it starts a TUI and a server. Where the TUI is the client that talks to the server. The server exposes an OpenAPI 3.1 spec endpoint. This endpoint is also used to generate an SDK… This architecture lets opencode support multiple clients and allows you to interact with opencode programmatically." Documented consequences:
- `opencode serve` runs a headless HTTP server (default port 4096, `127.0.0.1`); `opencode web` adds a browser UI; `opencode attach <url>` connects a TUI to a remote backend sharing "the same sessions and state" (`web.mdx`, `cli.mdx`).
- The IDE extension drives a running TUI via the server's `/tui/*` endpoints (`server.mdx`); `opencode acp` exposes the agent over the Agent Client Protocol via stdio nd-JSON (`acp.mdx`).
- All state lives server-side: sessions, messages, permissions, snapshots — the TUI is disposable. Events stream over SSE (`GET /event`, first event `server.connected`).

### 1.4 Zen (and Go): the optional paid gateway, philosophically framed
`zen.mdx`: "OpenCode Zen is an AI gateway that gives you access to these models… completely optional." Stated **Goals**: (1) benchmark the best model/provider combos for coding agents; (2) "highest quality… not downgrade performance or route to cheaper providers"; (3) "pass along any price drops by selling at cost; so the only markup is to cover our processing fees"; (4) "**no lock-in**… always let you use any other provider with OpenCode as well." `go.mdx` documents **OpenCode Go**, a $10/month subscription for open coding models aimed at international users — the subscription product, *not* the Go language.

### 1.5 Implementation history: Go → TypeScript/Bun, OpenTUI, and the in-flight v2 rewrite
- **Go→TS rewrite (documented indirectly):** no docs announcement, but `CONTRIBUTING.md` states the current stack: "packages/opencode: OpenCode core business logic & server; `src/cli/cmd/tui/`: The TUI code, written in SolidJS with opentui; `packages/app`: shared web UI (SolidJS); `packages/desktop`: Electron; `packages/plugin`: `@opencode-ai/plugin`." Deps on `@opentui/core|solid|keymap` confirm the renderer. A third-party changelog records: "OpenCode was historically a Go project (BubbleTea TUI). It has been completely rewritten to Bun/TypeScript… `Bun.build({compile:true})`." (Inferred: rewrite during the 0.x line in 2025; exact date unverified.)
- **v2 / next-generation architecture (documented in-repo):** `AGENTS.md` mandates the dependency direction "from **Schema to Core and Protocol, then from Core and Protocol to Server**… **sdk-next composes Client, Core, and Server**" (Client may not import Core/Server), requires codegen (`bun run generate` in `packages/client`) after changing "the public Protocol or Server `HttpApi`", and references "Effect generators" — matching `effect` (4.0.0-beta) deps across `packages/{core,llm,protocol,schema,server,client,sdk-next,cli}/package.json`. **Documented fact:** the new packages exist and are Effect-TS-based: `@opencode-ai/{schema,core,protocol,llm,server,client,sdk-next,tui,cli}`.
- `CONTEXT.md` ("OpenCode Session Runtime") is the team's domain-language spec for the v2 session engine (see glossary). On the public client: "The beta OpenCode Client currently uses plural consumer-facing capability groups such as `sessions`; whether the stable Session namespace should instead be singular `session` must be settled before stabilization." And: "`@opencode-ai/sdk-next`… will assume the existing `@opencode-ai/sdk` name after legacy consumers migrate."
- **v2 beta docs** (v2.opencode.ai): "These docs are for the beta version of OpenCode, which will become OpenCode 2.0… we may wipe your data, things may break, and APIs, configuration, and plugin APIs may change." Beta installs as `@opencode-ai/cli@next`, binary `opencode2`; its skill docs show a new permissions shape (`"permissions": [{action, resource, effect}]`) vs v1's `permission` map.
- Changelog (opencode.ai/changelog, Jun–Jul 2026) corroborates the migration: "Added the V2 plugin API for Effect and Promise plugins", "Preserve `V2Event` names in SSE streams", "Add paged durable session history", "Completed the Desktop v2 migration", "Added a code mode MCP adapter… Hid the `execute` tool unless code mode is enabled."

### 1.6 LSP & pragmatism
`lsp.mdx` documents 30+ built-in language servers feeding diagnostics to the agent, but also an unusually candid best-practices note: LSP "is not always a net positive… In many projects it is better to have the agent run lint, typecheck, or other diagnostic CLI tools directly." LSP is **disabled by default** (`lsp: true` to enable); the `lsp` *tool* is experimental behind `OPENCODE_EXPERIMENTAL_LSP_TOOL`.

## 2. Feature-level mental model (what to know before reading code)

**Sessions.** The durable unit of work. A session belongs to a *project* (a working directory; git worktree-aware). Sessions form trees: subagent invocations create **child sessions** (`/session/:id/children`, TUI `session_child_*`/`session_parent` keybinds). Sessions can be forked at a message (`/session/:id/fork`), shared (`/share` → `opncd.ai/s/<id>`), compacted (`/compact`, auto on full context, `compaction.{auto,prune,reserved}`), and reverted — `/undo`/`/redo` restore conversation and file changes via **snapshots**, which "use Git to manage the file changes" so the project must be a git repo (`tui.mdx`, `config.mdx#snapshot`). Hidden system agents **compaction**, **title**, **summary** run automatically; `small_model` covers light tasks like titles.

**Agents & modes.** Two kinds: **primary** (you converse with; cycle with Tab) and **subagents** (invoked by primaries via the Task tool or by `@mention`). Built-ins (`agents.mdx`): **build** (default, all tools), **plan** (restricted: edits and bash default to `ask`), **general** (full tools except todo, for parallel work), **explore** (fast read-only codebase search), **scout** (read-only external/dependency research, experimental). Agents are configured in JSON (`agent` key) or Markdown frontmatter (`~/.config/opencode/agents/`, `.opencode/agents/`) with `description` (required), `mode` (`primary|subagent|all`), `model`, `prompt` (supports `{file:…}`), `temperature`, `top_p`, `steps` (max agentic iterations; `maxSteps` deprecated), `hidden`, `color`, `disable`, plus pass-through provider options. Global keys: `default_agent`, `subagent_depth` (default 1). Interactive creation: `opencode agent create`.

**Tools & permissions.** Built-in tools (`tools.mdx`): `bash`, `edit` (exact string replacement), `write`, `read`, `grep`, `glob` (both ripgrep-backed, respect `.gitignore`/`.ignore`), `apply_patch`, `lsp` (experimental), `skill`, `todowrite`/`todoread`, `webfetch`, `websearch` (Exa; needs OpenCode provider or `OPENCODE_ENABLE_EXA`), `question`, `task` (subagents). Since **v1.1.1** the legacy boolean `tools` config is deprecated into a unified **`permission`** system: every rule resolves to `allow | ask | deny`; object syntax maps glob patterns → action; **last matching rule wins**; patterns match tool names (so `mymcp_*` works for MCP tools) and inputs (bash command lines, file paths, URLs). Defaults: mostly `allow`; `doom_loop` (same tool call 3× identically) and `external_directory` default to `ask`; `*.env` reads denied by default. `ask` UI offers once/always(session-scoped)/reject. `--auto` approves anything not explicitly `deny`. Per-agent `permission` merges over global. **Policies** (`experimental.policies`, `{effect, action, resource}`) are separate: they gate *resource use* (currently `provider.use`), not tool actions.

**Config layering** (`config.mdx`). JSON/JSONC, schema at `opencode.ai/config.json` (TUI settings live in a separate `tui.json`, schema `opencode.ai/tui.json`). Files **merge**, not replace. Precedence (low→high): remote `.well-known/opencode` org defaults → global `~/.config/opencode/opencode.json` → `OPENCODE_CONFIG` → project `opencode.json` → `.opencode` dirs (agents/commands/plugins/skills/tools; plural names, singular supported) → `OPENCODE_CONFIG_CONTENT` inline → managed files (`/Library/Application Support/opencode/`, `/etc/opencode/`, `%ProgramData%\opencode`) → macOS MDM `ai.opencode.managed` (not user-overridable). Substitution: `{env:VAR}`, `{file:path}`. Project config is found by traversing up to the nearest git directory and is safe to commit.

**Rules.** `AGENTS.md` (project, commit to git; `/init` generates it), `~/.config/opencode/AGENTS.md` (global), plus **Claude Code compatibility**: `CLAUDE.md` fallbacks, `~/.claude/skills/` and `~/.agents/skills/` loaded (disable via `OPENCODE_DISABLE_CLAUDE_CODE*`). `instructions` array takes globs and remote URLs (5s timeout).

**Commands.** `/name` prompts from markdown (`.opencode/commands/`) or JSON `command` key; support `$ARGUMENTS`/`$1..$n`, `` !`shell` `` output injection, `@file` inclusion; frontmatter `agent`, `model`, `subtask` (force subagent run). Custom commands override built-ins.

**Skills.** Agent Skills standard: `<name>/SKILL.md` with `name`+`description` frontmatter, discovered from `.opencode/skills/`, `.claude/skills/`, `.agents/skills/` (walk-up + global). Advertised in the `skill` tool's `<available_skills>` description; loaded on demand via `skill({name})`; gated by `skill` permission. (v2 adds flat `.md` skills, HTTP catalogs, `skills` config array.)

**Plugins.** JS/TS modules exporting async functions `(ctx {project, client, $, directory, worktree}) → hooks`. Loaded from `.opencode/plugins/`, `~/.config/opencode/plugins/`, or npm (`plugin` array; Bun-installed into `~/.cache/opencode/node_modules/`). Documented hooks: `event` (bus: `session.*`, `message.*`, `file.edited`, `file.watcher.updated`, `permission.asked/replied`, `lsp.*`, `todo.updated`, `server.connected`, `command.executed`, `installation.updated`), `tool.execute.before/after`, `shell.env`, `tui.prompt.append`, `tui.command.execute`, `tui.toast.show`, `tool` (register custom tools), `experimental.session.compacting`. Plugin tools override same-named built-ins. Types from `@opencode-ai/plugin` (`Plugin`, `tool`, `tool.schema` = Zod).

**MCP.** `mcp` config: `type: "local"` (`command`, `environment`, `cwd`, `timeout` 5s) or `type: "remote"` (`url`, `headers`, `oauth` — auto OAuth w/ dynamic client registration, tokens in `~/.local/share/opencode/mcp-auth.json`, CLI `opencode mcp auth/list/logout/debug`). Tools registered as `<servername>_*`; warned to add context weight. Org defaults can ship disabled via `.well-known/opencode` and be enabled locally.

**Models/providers.** AI SDK + Models.dev registry ("75+ providers"); credentials via `/connect` → `~/.local/share/opencode/auth.json`; model IDs `provider/model`; **variants** (Anthropic `high`/`max` thinking budgets; OpenAI `none…xhigh`) cycled with `variant_cycle` (ctrl+t); per-model `options`, `blacklist`/`whitelist`, `baseURL`; selection order: `--model` flag → config `model` → last used → internal priority.

**Interfaces.** TUI (leader key `ctrl+x`, palette `ctrl+p`, `@` file refs, `!` shell, image drag-drop); CLI (`run [--format json|--attach]`, `serve`, `web`, `attach`, `agent`, `auth`, `mcp`, `models`, `session`, `export`/`import`, `github`, `acp`, `upgrade`, `db`, `debug`…); Web (`opencode web`, mDNS); IDE extension (auto-installs from VS Code-family terminal, drives TUI via `/tui/*`); ACP (Zed, JetBrains, Neovim — "works the same via ACP", minus `/undo`/`/redo`); GitHub agent (`/opencode`/`/oc` comments → Actions runner); GitLab (CI component/Duo).

## 3. What docs promise that matters for cloning/extending the agent core

1. **Published, stable schemas:** `https://opencode.ai/config.json` and `/tui.json` — the config surface is a versioned public contract with documented deprecations (`tools` bool → `permission` at v1.1.1 but "still supported"; `maxSteps` → `steps`; legacy `theme`/`keybinds`/`tui` keys "automatically migrated"; singular dir names kept "for backwards compatibility"). `experimental.*` is explicitly unstable ("may change or be removed without notice").
2. **OpenAPI 3.1 spec** served at `/doc` on any running server; SDK types are generated from it (`packages/sdk/js/src/gen/types.gen.ts`). `@opencode-ai/sdk` (`createOpencode` spawns server+client; `createOpencodeClient` attaches) exposes sessions/messages/files/find/tui/auth/events with typed errors and `json_schema` structured output. The HTTP API is the supported extension boundary — not internal TS modules.
3. **Plugin API** (`@opencode-ai/plugin`) is the documented way to add tools/hooks; plugins get an SDK `client`. Custom tools use Zod args; filename = tool name; multiple exports → `<file>_<export>`.
4. **Multi-client is a first-class promise**: same agent core behind TUI, web, desktop, IDE, ACP, GitHub Actions — all through the server.
5. **Data ownership:** "You own all code produced by OpenCode" (`enterprise.mdx`); sessions stored locally (`~/.local/share/opencode/project/<slug>/storage/`); share pages are the only cloud upload and can be `disabled`/self-hosted.
6. **v2 instability warning (critical for cloners):** v2.opencode.ai warns APIs, configuration, and plugin APIs may change; `CONTEXT.md` lists unsettled public decisions (`session` vs `sessions` namespace, Page envelope projection, `sdk-next` → `sdk` rename after migration). Documented design constraints for the new stack: dependency direction Schema→Core/Protocol→Server; Client never imports Core/Server; root `@opencode-ai/client` is zero-Effect with `/effect` subpath; `sdk-next` runs Server's `HttpRouter` in-memory ("Embedded OpenCode" — same handlers, no socket); durable session event stream `sessions.events({after})` vs live `events.subscribe()` with no replay.
7. **Environment-variable contract:** ~25 documented `OPENCODE_*` vars (config paths, permissions inline JSON, feature flags for native LLM path `OPENCODE_EXPERIMENTAL_NATIVE_LLM`, event system, workspaces, background subagents, plan mode).

## 4. Glossary of OpenCode-specific terms

- **Session** — durable conversation unit belonging to a project; tree structure (parent/**child sessions** from subagents); can be **forked**, **reverted/unreverted** (git snapshots), **shared**, **compacted**.
- **Project / worktree / directory** — working context: `directory` = cwd, `worktree` = git root; project config discovered by walking up to the git root.
- **Agent** — named bundle of prompt + model + permissions + mode. **Primary** agents are user-facing (Tab cycles); **subagents** run as child sessions via the Task tool or `@mention`. **Mode** ∈ `primary | subagent | all`.
- **Build / Plan** — the two built-in primaries: full-access default vs restricted analysis mode. **General / Explore / Scout** — built-in subagents. **Compaction / Title / Summary** — hidden system agents.
- **Permission** — tri-state rule (`allow | ask | deny`) keyed by tool name + input globs; last match wins; **auto mode** (`--auto`) pre-approves non-denied asks.
- **doom_loop** — guard tripped when the same tool call repeats 3× identically (default `ask`). **external_directory** — guard for paths outside the project worktree.
- **Snapshot** — internal git tracking of file changes enabling `/undo` & `/redo`. **Compaction** — context summarization (auto; `prune` drops old tool outputs). **steps** — max agentic iterations per prompt.
- **Command** — user-defined slash command (markdown/JSON template with `$ARGUMENTS`, `` !`shell` ``, `@file`); **subtask** forces subagent execution.
- **Skill** — discoverable `SKILL.md` package of reusable instructions, advertised via the `skill` tool and permission-gated; compatible with `.claude/skills` and `.agents/skills`.
- **Plugin** — JS/TS module hooking events/tool execution or registering tools; **custom tool** — user function (any language via shell-out) exposed to the LLM.
- **MCP** — Model Context Protocol servers (local stdio / remote HTTP+OAuth); tools register as `<name>_*`.
- **Provider / model id / variant / small_model** — Models.dev-backed LLM source; `provider/model` addressing; variant = named option preset (reasoning effort); small_model = cheap model for titles/light tasks.
- **Zen** — optional curated AI gateway (pay-per-request, at-cost pricing, zero-retention providers, team **workspaces** with roles/limits). **Go** — $10/mo subscription tier for open models.
- **Share** — opt-in public link sync of a session to opencode.ai (`opncd.ai/s/<id>`); modes manual/auto/disabled.
- **Server / instance** — headless HTTP core (OpenAPI 3.1, SSE events, optional basic auth, mDNS); **TUI** — SolidJS/OpenTUI terminal client; **leader key** — `ctrl+x` keybind prefix.
- **ACP** — Agent Client Protocol server mode (`opencode acp`) for editor integration.
- **Reference** — aliased external directory or git repo added to context (`references` config), surfaced in `@` autocomplete.
- **V2 session-runtime vocabulary** (`CONTEXT.md` spec): **System Context** (assembled initial instructions; "avoid: system prompt") built from keyed **Context Sources**; **Baseline System Context / Context Epoch** (immutable cache-friendly prefix and its lifetime); **Mid-Conversation System Message** (durable chronological context update); **Provider Turn**; **Session Drain** (process-local execution span); **Admitted Prompt / Prompt Promotion**; **Model Tool Output / Managed Tool Output File** (bounded tool results + overflow files); **OpenCode Client / Embedded OpenCode / SDK Contract IR** (generated API; in-memory host; codegen IR); **Location**; **Page** (cursor-paginated result).
- **Workspace** — (a) Zen team workspace (roles, model access, spend limits); (b) experimental multi-root workspace support behind `OPENCODE_EXPERIMENTAL_WORKSPACES`.
